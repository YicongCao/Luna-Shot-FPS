## 几何与UV检查

不能仅凭20,901三角不变判定保形。本次逐个比较三角面角点，允许顶点/索引重新排序和三角面起始角点循环排列，不允许绕序翻转。

- 20,901面全部匹配，无遗漏、无新增面。
- Tripo把输入包围盒居中，等比缩放`0.8413944490346557`。使用服务返回的缩放值和输入中心逆变换后，最大位置差`4.8818656539570805e-08`源单位，低于`2e-6`检查阈值。没有拟合非均匀缩放或变形掩盖误差。
- 所有62,703个匹配角点的UV差值**严格为0**。没有换UV或重新展开。
- 顶点多10个，但表面几何与UV逐面对应，属于额外拆点，不是新增设计或轮廓变化。
- 原文件SHA256仍为`d7591f026d423e57339de505650690eeb8fd7da30e7871007a6662106bef8319`，未被修改。

**顶点法线并非完全相同。** 原模型18个零长度法线角点变为有效法线；其他有效法线角点的方向差中位数0.00199°、P95 0.00374°。其中6个方向差超过0.1°，最大26.17°。这是必须披露的服务处理，不能写成“所有网格数据原样保留”。当前灰模整体形体相同，但法线精确保持不通过，后续实际游戏使用前仍需定位这些局部变化。

检查脚本保留5个保护测试：索引重排/已知等比归一可通过；顶点变形、UV变动、绕序翻转、法线改动均能被检测。详见[audit.json](audit.json)、[gate-tests.log](gate-tests.log)。

## 材质通道与视觉观察

主要PBR通道实际存在并绑定：4K底色、4K切线法线、4K金属度/粗糙度合并图。MR的G为粗糙度，B为金属度，R全白且没有occlusion绑定；没有独立AO、Emission、Clearcoat等。此次“完整PBR”指BaseColor/Normal/Roughness/Metallic四个主要通道，并非所有可选物理材质通道。

收益：

- 相比只有底色且metallic=0、roughness=1的混元输入，新增真实的金属/粗糙度变化与贴图法线，灯光下能看到反射和细节响应。
- 原有弹夹分段、卡扣、枪托镂空、前罩孔槽保持，没有ML07删减结构的问题。
- UV完全一致，后续可以在同一UV上独立比较颜色与材质响应，不必重展UV。

问题：

1. **色块没有完全保持。** 枪托上壳、部分机匣从原白色变成深灰。仅底色无光照模式也存在该变化，故不是纯粹由反射变暗导致。少量橙色标记位置/文字也被重绘。
2. **偏亮滑。** 深色框架、握把和橙色弹夹呈较强的平滑高光，尚未达到稳定区分涂漆金属、裸金属、橡胶的目标。提示词中的“橡胶非金属”和“避免统一铬亮感”不能当作实际生成质量保证。
3. **波浪高光更明显。** 关闭贴图法线后，大平面仍有起伏高光，说明不是新Normal贴图单独造成；原低模/顶点法线与新的反射参数共同影响观感。没有凭外观再次减面或重建。
4. **油污/做旧未达到目标。** 有细碎边缘与表面纹理，但未形成概念中有控制的局部油膜、露底和接触区磨损；不能因通道数量增加而称美术通过。
5. 青色能量环本次为服务颜色/材质，不含独立主动发光或邻近结构补光；原游戏ML06的能量效果保持不变。

判断：**这次试验证明“保留混元几何和UV，单独交给Tripo生成PBR”可行；没有证明这版材质比混元原底色版更好。** 保留为候选和对照，不自动推广。

Godot 4.7.2 Compatibility，Apple M5，1400×900；统一正交相机、环境、曝光、0.905m枪长，原始模型分别居中/等比归一以对应展示。两组光照：中性光、掠射光。

36张原生截图，覆盖三版本的最终材质、灰模、法线关闭、仅底色和左右侧/近景。主流程36条检查记录，补充底色12条记录，共48条均成功（其中包含重复导入/统计记录）；法线开启/关闭实际像素响应保存在[verification.json](verification.json)。日志无脚本错误。

比较范围统一为枪械主体，排除后加工业kit、动态弹药屏、红点、局部补光；Emission与Bloom关闭。ML06以现有材质绑定加载。原生场景在项目内通过GLTFDocument读取归档候选，`.gdignore`保护其他制作源不被自动导入。

这不是完整训练场第一人称接入：未测候选换弹、命中、开镜、碰撞、超宽或60秒性能；没有改动默认运行时资源，故没有把静态材料检查冒充游戏回归。
