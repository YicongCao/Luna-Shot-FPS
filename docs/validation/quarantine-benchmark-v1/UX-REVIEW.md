# 关卡与终端交互 UX 复查

2026-11-17。按用户要求，以状态可见性、信息层级、操作预期、错误预防和流程连续性检查独立 Quarantine 关卡。范围不扩展到原训练场。

## 发现与处理

| 问题 | 造成的理解成本 | 调整 |
|---|---|---|
| 同一终端的顶部与屏幕重复电源图标 | 不能区分设备状态、操作入口和下一步 | 删除两套终端标识，改成唯一设备投射面板；原屏幕位置成为发光投射槽，不再是第二个显示界面 |
| `0%` 和击杀数量混在任务列表 | 单个终端被表达成抽象百分比，完成条件不统一 | HUD 三项分别为害虫 `n/8`、终端 `0/1`、撤离 `0/1`；按住动作仅用秒数和填充反馈 |
| 大段英文、重复品牌/战术标签 | 玩家需阅读大量非功能信息 | 移除装饰性 HUD 文案和场景 Label3D；世界标牌使用附着于实体的电气危险、锁与出口图标 |
| 只有目标距离，没有方位 | 距离变大/变小不是充分导航 | 终端和撤离点添加屏内图标定位、离屏/背后方向箭头；不把敌人做成透墙目标 |
| 只要距离近就可以按 E | 背对设备、从背后或隔墙操作不符合预期 | 交互要求清剿完成、3m 内、设备前侧、看向面板且物理视线无遮挡 |
| 进度缺少明确中断契约 | 转身/离开后反馈与完成状态可能不一致 | 松手、转身、离开或遮挡都会清空连续按住进度；只有完整 3 秒才提交 `1/1` |
| 完成后仍停留在开机界面 | 玩家需要自行推断撤离流程 | 面板立即切换出口图标、必要动作“前往撤离点”和距离；HUD 同时切换撤离定位 |
| 受击只有普通火花与侧翻 | 难以感受到电击失能的因果 | 增加接触驱动的壳面电弧、核心闪断、肢体抽动、局部装甲变暗/松脱和短暂残余放电 |

## 信息架构

- **远处**：HUD 负责目标方向与任务数量，不常驻长说明。
- **靠近设备**：全息面板负责当前条件和唯一主操作。面板清楚可读时隐藏重复 HUD 操作提示和终端定位标记。
- **操作中**：E 键框、剩余秒数、填充反馈；任务数量保持 `0/1`，完成时才变 `1/1`。
- **完成后**：面板和 HUD 都转向撤离，但分别承担局部结果/下一步提示与全局方向定位。
- **失败/暂停**：保留“已暂停 / 任务失败 / 撤离成功”和“继续 / 重试”等必要功能文案，不用口号替代状态。

## 全息面板的约束

面板由 Godot SubViewport 绘制到实际世界空间 QuadMesh，有边框与从设备投射槽到面板的连接线，受世界透视和遮挡影响。7m 内、设备前方且无遮挡时显现；近距离可读时接管 HUD 提示。不是屏幕空间悬浮字，也不是新 imagegen 图或离线合成。

场景中的电气设施标识用闪电图标，避免建筑上遥不可及的“电源按钮”与可操作终端混淆。终端只出现一个当前阶段主图标。

## 验证边界

实现侧复查和自动化通过不等于真实新手可用性测试。尚未做多名玩家首次游玩、手柄、色觉障碍与各类显示尺寸测试。原共享资产贴图中的小型烘焙字样没有破坏性擦除；本轮清理的是独立场景的可见 Label3D 和新界面。

电击效果是有明确预算、真实命中驱动的程序表现，不是完整物理断裂、熔穿或材料损伤模拟。Benchmark 敌人站位/镜头有编排；五只敌人在剪辑点清除，不能将演示当作无人干预通关。
