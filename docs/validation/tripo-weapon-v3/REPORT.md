## 原生检查与视觉结论

独立GLTFDocument读取源目录，未把2M高模加入默认游戏。原生14项导入/截图检查通过，输出12张同机位PBR/灰模/关闭法线截图，摄像机、曝光和光照一致。分别关闭高/低模法线后，在枪械画面区域出现25,012/34,795个RGB平均差超过2%的像素，证明服务法线实际参与渲染；不等于证明法线每处正确。

观察：高模保持原枪托镂空、分段能源盒、机匣分层，低模同样保留了这些整体设计，优于ML07重建分支删掉相关结构的做法。低模灰模依然有明显软边、三角起伏，加载法线后部分细节恢复，但未全部达到高模的锐利程度；机匣和前罩尤其需要继续审查。故本轮“服务任务与原生导入通过”，视觉仍开放，用户验收待定；不自动替换ML06。

当前候选基于最初枪械，不含后来加的工业kit、20格屏幕、铜管/散热片附件。生成字标也不是精确LS01工业字形。青色环在底色中可见，但没有Emission通道或主动补光。新资产尚未接入射击、换弹、红点、弹药屏与能量接口，未做这些功能回归或60秒性能测量。

本轮可以证明Tripo确实返回了带Normal的低模并完成纹理转移；公开工具的bake标志没有暴露高低模cage/射线配对，不能宣称等同手工控制的Cycles几何法线投射。几何问题不能因为存在normalTexture就算解决。

## 可复现与后续

原始来源/请求/任务/费用位于art_source/weapons/lc01/tripo-rebuild-v3，.gdignore避免高模常规导入。audit.py读取GLB并无损提取图像；capture.gd在Godot中直接加载服务材质；report.py生成图集。先执行python3 tools/tripo_weapon/audit.py，再godot --path . --script tools/tripo_weapon/capture.gd，最后uv run --with pillow --with numpy python tools/tripo_weapon/report.py；这些本地步骤不重新提交付费任务。

后续应先决定20k候选软边是否可接受。若不可接受，研究按部件分配预算/支持更高面数的受控减面与真实法线投射路线；需要另列工具能力和费用，不在本轮自动追加生成。优先保留现有高模，禁止回到整件程序化重建。可在用户选择候选后再适配既有动画/能量/屏幕附件，避免现在的模型实验覆盖已认可默认枪。

首次原生脚本发生GDScript路径类型推断错误，显式声明String后修正，最终日志无错误。静态图源与费用/模型数据已核查，HTML交互未使用浏览器实测。
