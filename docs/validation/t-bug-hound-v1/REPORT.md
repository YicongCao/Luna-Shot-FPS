# ML32 · 六足机械猎犬

[同机位原生图集：旧虫壳 / 机械犬](views/index.html) · [演示中的实际特写](closeup/closeup.png) · [受击与动作测量](checks/headless.json) · [步态回归](gait/metrics.json)

**体验：** `./launch-quarantine.command` 直接游玩。`QUARANTINE_BUG_STYLE=refined ./launch-quarantine.command` 使用上一版机械虫；`baseline` 看更早的球体版。默认和 `hound` 为新犬形。`./launch-benchmark.command` 是独立实时演示，其特写里的扫视是编排动作，不是自主发现玩家。

### 造型的收益和损失

上一版低矮的传感器盒与两根长触须，从侧面首先读成机械昆虫。本轮换掉整个躯壳：抬起头轴与斜颈，拓宽肩部、收腰，在后躯增加配重；没有添加武器。六片可独立受击的护板改为沿壳体侧面安装，保留六腿、可见关节和落脚节奏。采用程序网格与已有工业材质，没有新生成服务调用、外部模型或新高模烘焙。

首轮的头在灰模中像一整块喙，三组等大的鞍板掩盖了腰线。第二轮增加分开的下颚、后掠接收器，并缩小腰侧检修盖。左右背面剔除实拍里都能看到颚间空隙和颈轴，未观察到大块外壳翻面。**实玩读形有距离限制：** 5.59 m、72° 腰射视野的路线阴影中，抬起的双眼与头顶轮廓仍清楚，但吻部、腰线、远侧腿根会融入躯壳；旧版橙色背脊在逆光中反而更易追踪。没有为对照调亮全场；只有灰模诊断使用临时补光。

### 动作与命中反馈

- 巡逻时头部左右停看；发现原 AI 可以看见的玩家才转头追视。近战在既有伤害时点下探并回收。没有给追逐、攻击或玩家伤害添加新判定。
- 实际射线命中后，头部按接触法线偏转，最近一片护板压入、回弹并留有局部烧痕。非致命弹不再于渲染帧抖动带支撑脚的髋根。死亡时头下垂，护板仍挂在机身上，残弧逐渐消失，不是物理破碎。
- 相反两侧实射：受击侧护板压入约 **47 mm** 后复位，头部产生符号相反的约 **20°** 局部偏航；同伴材质和其余护板不受影响，站定姿态的受击渲染回调中支撑脚未测得漂移。第三发只记一次死亡，第四发不再命中尸体。原近战每次 12 HP；本次测试两次扣血间隔 69 个 60 Hz 物理步。连续墙后左右换位未改变头和身体轨迹。
- 胶囊仍为半径 **0.43 m**、高 **0.90 m**；眼、吻、伸出的腿等并非独立命中区。**瞄躯干**可稳定命中，只打到胶囊外的可见部件不会计伤。没有爆头倍率，也没有对目标吸附。

### 验证范围

Godot 4.7.2 / macOS / Metal Forward+。33 项动作及命中检查，83 项步态夹具检查。原生侧拍、腰射和动作序列为 9 对匹配图（每版 17 项捕获检查）；实际扣弹 20→19、敌人生命 3→2。场上站位和步进由脚本安排，不是无人为干预的游玩录像。21 秒特写的整体留边、相机与焦点等 5 项检查通过。详见 [原生帧状态](views/hound/frames.json)。

最终完整回归：49 项任务、69 项旧训练场、24 项命中与交互反馈、12 项实时演示、20 项重播/实玩衔接通过；实际启动器的无截屏演示也通过。首轮诊断窗口与演示同时运行，已主动中断并改为串行；这里不使用那轮的性能或部分演示结果。[完整演示结果](validation/native/result.json) · [衔接验证](validation/controls.json)。

**活虫路线，而非冻结敌人的演示 FPS：** Apple M6 / Metal / 1920×810，VSync 请求关闭，分别运行 60 秒，两个版本均使用 ML31 落脚。旧壳 → 新犬形：平均 81.20 → 79.96 FPS，P95 14.334 → 14.553 ms，P99 15.067 → 15.378 ms。分别完成 12 / 11 个路点，累计活虫位移 487.6 / 464.0 m。不是逐帧相同的视野或负载，末帧 draw calls 不宜解释成模型单体成本。详见[旧壳](active-refined/native.json)与[犬形](active-hound/native.json)。

复现：`tools/validate_hound.sh`，默认写入新 `artifacts/hound-时间戳` 而非历史材料。固定帧对照、限时演示和 60 秒活虫路线分开，避免并发窗口影响计时。已知退出时的 Metal Texture RID 警告仍在。以上不是用户美术验收，也不是对整体 3A 照片级完成度的认定。
