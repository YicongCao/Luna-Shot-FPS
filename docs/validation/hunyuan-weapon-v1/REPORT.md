# ML18 — 混元枪械与 Tripo / 本地重建路线评估

日期：2026-11-16。范围：用户提供的四个文件、ML17 Tripo 全链路候选、ML06 运行时主体、ML07 局部重建分支。没有替换默认资产，没有收费调用。

## 结论

**下一轮几何试验优先使用这批混元产物；当前游戏保留 ML06；完整生成 PBR 和独立分件的现成程度，Tripo ML17 更完整；不再推广 ML07 那种整片简化后重建的做法。**

这不是“混元在所有方面胜过 Tripo”：混元低模的主要结构清晰、色块干净，但也有软边和大平面不连续阴影；提交的所谓 PBR 文件只有底色。它更适合作为新候选，尚不满足直接替换现有枪械的要求。

- **看造型和轮廓**：混元高模保留了弹夹分段、端盖/卡扣、机匣叠层、枪托开口、瞄具脚座；没有 ML07 删除设计层次的问题。原 Tripo 高模和 ML06 保留高模也保有这些设计，不能说它们本来就差。
- **看约 2 万三角的实际表现**：混元在机匣分区、前罩、弹夹台阶的结构辨识上更清楚；Tripo ML17 低模的凹凸和三角阴影更杂乱。混元灰模近景仍有鼓包式阴影、圆钝过渡、低分辨率孔槽，不能算精准硬表面成品。
- **看材质**：混元彩色图显得干净、风格统一，但金属/粗糙度分布缺失；Tripo 通道齐、微表面丰富，却不能靠贴图恢复低模丢失的轮廓，部分表面显得脏碎。ML06 的明亮金属反射更强，也有过亮和不均匀质感，不能把亮等同于正确。ML07 虽有分层 PBR，结构倒退仍是主要问题。
- **看工程可用性**：混元是一个网格/材质槽，不能直接使用现有按零件名称驱动的弹夹动画、能量环和绑定表。Tripo ML17 保留 18 个网格/材质，后续挂接更方便，但它也没有本地后加的动态弹药屏、铜排和散热片。ML06 已接入完整游戏，因此继续作为默认和功能基线。

## 1. 四个混元文件的真实内容

| 文件 | 磁盘大小（十进制） | 三角数 | UV / 材质 | 判断 |
|---|---:|---:|---|---|
| 高模.glb | 35.86 MB | 1,992,214 | 无UV、无贴图、无存储顶点法线 | 高密度几何源；导入器生成法线 |
| 低模.glb | 0.38 MB | 20,945（GLB/Godot）；20,925（Blender导入后） | 无UV、无贴图、无存储顶点法线 | 裸低模；两个导入器保留面数不同 |
| uv展开.fbx | 1.53 MB | 三角化后20,901；原20,474多边形 | 一套UV，无材质贴图 | UV后的网格，并非与裸低模面表完全一样 |
| pbr材质.glb | 9.93 MB | 20,901 | 一套UV、顶点法线、一个材质、一张8192×8192底色图 | **不是一套完整PBR贴图** |

最终 GLB 的材质 JSON 只有 `baseColorTexture`，`metallicFactor=0.0`、`roughnessFactor=1.0`。没有 `normalTexture`、`metallicRoughnessTexture`、`occlusionTexture`、`emissiveTexture`；发光因子也为零。青色能量环只是底色，在当前文件内没有主动发光。标准 glTF 的 PBR 材质对象名称，不等于已经提供了完整的贴图通道。

**这只能证明本次交付文件缺通道，不能证明混元服务不支持这些通道。** 可能涉及导出选项或还未提供的文件；没有混元任务版本、输入视图、参数、生成费用和任务编号，本次不猜测具体原因，也不评价单位付费成本。

底色图本身有亮边、暗缝与色块明暗；原生图中一部分细节因此显得立体，但这些是固定颜色信息，不能代替随灯光变化的法线和材质反射。没有擅自把它转换成高度/法线/粗糙度。

8K底色是文件体积的重要来源。供预算参考：8192² RGBA8 未压缩单层为256 MiB，含完整mipmap约341 MiB；这是理论大小，不是本次GPU纹理内存实测，也不表示导入后一定采用该格式。Tripo低模6.96 MB反而含54张图，因此不能用GLB大小判断哪件更精细。

## 2. 与两条历史路线的区别

| 路线 | 高模 | 低模/运行时主体 | 真实特点 |
|---|---:|---:|---|
| 混元此次交付 | 1,992,214 | 最终20,901 | 主要设计保留，结构较清楚；单网格；材质通道不齐 |
| Tripo ML17全链路 | PBR高模1,934,290 | 20,303 | 18网格、18材质、54张图；低模仍有软边/三角起伏 |
| ML06保留与修整 | 1,934,277 | 19,658（主体） | 高模几乎保留原Tripo；低模含历史Tripo重拓扑，再本地修复/烘焙/材质加工 |
| ML07局部重建 | 展示42,520（含未重建低模参照） | 源配对20,032；运行时主体22,272 | 多个大件被简化为大平板，丢失分段/镂空/装配层次；本地分层PBR无法挽回 |

原 Tripo 几何是1,934,304三角。ML17纹理任务返回1,934,290，不能宣称与原文件逐顶点一致。ML07高模列含11个未重建低模零件作为相同装配参照，不是完整全枪高模；运行时主体多了导出阶段的螺钉副本，故与源配对面数不同。

必须修正“Tripo做高模、Codex做所有低模”的泛化说法：ML06原低模来自历史Tripo远程重拓扑，后续才由本地修复；ML07才发生主要机械件程序化重建。ML06的软化与ML07的设计删减，不能归为同一项操作。

本轮原生对比排除所有后加工业kit和动态附件，避免某一列凭更多附件获得优势。ML07移除的是名为IndustrialKit的组，其主体/保留件和绑定材质保留。**这些图是主体评估，不是完整玩家枪械组装效果。**

## 3. 原生观察及技术检查

- Godot 4.7.2 Compatibility，Apple M5；独立材料场景，1400×900，固定正交相机、灯光、环境和曝光，0.905m等比归一；统一关闭Emission与Bloom。七组网格、两侧及近景，彩色/灰模/法线关闭对照。
- 67项导入、截图与统计记录通过，53张原生截图。只说明本次静态检查成功，**未测试混元版本的换弹、开镜、射击、碰撞、60秒帧时间或超宽窗口**。
- 额外27张 Blender Workbench 离线灰模用于高低模和历史源文件比较；与原生图区分。只刚性变换与等比缩放，不重算法线、不改拓扑、不重展UV、不修复文件。对于未存储法线的GLB，由各自导入器生成显示法线；这是解释不同软件显示差异的必要边界。
- 灰模去掉贴图法线但保留顶点法线，因此波浪阴影可能由几何和顶点法线共同造成，不能只凭截图把它全部归咎于减面或平滑参数。
- 混元高模：索引拓扑检查未发现边界边或>2面共边，10个极小面积面（阈值1e-14，按源单位）；这不是完整自交/正反面认证。
- 混元裸低模：Blender导入后有556条边界边、133条>2面共边，20个极小面积面；它与UV/最终网格面数不同，需在后续生产时定位，不把它当成干净拓扑直接发布。
- UV FBX与最终GLB的世界空间顶点位置集合（保留6位小数）一致，面数相同；最终GLB因UV/法线拆分有17,971顶点，FBX为10,715。**这不证明逐面UV编号、三角化顺序完全相同**；保留各自文件，不互换旧烘焙。
- UV循环坐标均在0–1内。最终GLB有大量索引边界，其中包含UV接缝拆点，不能解释成同等数量的实际破洞；没有执行完整UV岛重叠、cage投射、穿插、全角度背面剔除验收。
- 法线开关像素差记录见verification.json；混元没有贴图法线，关闭它不改变枪械画面。Tripo/ML06/ML07的法线图会影响实际渲染，但有影响不代表正确。
- 混元高/低模原始包围盒中心、长度略有差异，正式高→低烘焙前必须验证空间配对；本轮展示归一不能冒充已验证的烘焙对齐。

## 4. 建议如何选择与继续

1. **下一轮只选混元为几何候选**，保留高模、UV后的最终低模和当前色块，先不重建整枪。现在的收益来自设计保留，不能再为了“整洁”删除设计。
2. 先核实混元是否还有独立Normal/Roughness/Metallic导出。若有，按其通道定义接入测试；若没有，选橙色弹夹+机匣局部做真正高→低法线与独立粗糙度/金属度样板，验证锐边、波浪、接缝及掠射光。
3. 保留混元造型做有限的法线/拓扑修复与分件，分离换弹件、能量环及固定枪身；再接入现有红点、弹药屏、铜管/散热片和挂点。单网格或连通分量数量不能替代语义分件清单。
4. 不将Tripo现有PBR直接套在混元网格：UV不兼容；如采用跨工具纹理服务，必须明确对新网格重绘/转移，并验证其保持几何与UV的行为。也不把底色灰度自动当作金属度或高度。
5. 样板过关后，在正常第一人称、转动光照和功能回归下与完整ML06比较，记录收益与损失；用户认可前不替换默认。混元8K图是否降到4K/2K需同镜头判断，本轮未改图。

如果只问“现在直接用哪个”：**游戏继续ML06；完整自动材质候选选Tripo；新一轮形体改进优先混元；ML07整体重建不选。**
