## 这次只改任务高潮

不改玩家路线、武器、塔资产、雾色或曝光。在清剿副本现有塔上装三组有卡座和斜撑的固定绕组：待机弱亮，终端完成后自下向上短暂提亮，再进入稳定工作态。柱体无端盖，发光丝束按实际高度逐渐淡出；脚下的恢复脉冲只改变既有铺装材质，强调板缝，遮挡处不另画悬浮圆环。这是游戏着色器效果，不是体积流体或真实供电模拟。完成撤离不再次点火，重启后复位。`QUARANTINE_REACTOR=baseline` 回看旧光效。

[同机位对照](review.html)：左为ML29原生输出，右为本版。机位相同、采样时间不同，可判断端盖和安装结构，不能据此比较瞬间亮度。`validation/` 保留首轮：塔柱改善，但旧波环放大后像一片亮色几何，因此改成地板响应。新版牺牲了旧塔环待机时的远距离亮度，换来开机前后更清楚的反差；没有靠增加全场Bloom补回亮度。

## 验证范围

- `tools/quarantine/test_reactor_induction.gd`：9项定点状态检查，含首层先亮、结束不重播、重新部署清除残留。该脚本直接驱动状态，只验证呈现逻辑。日志 `sequence.log`。
- 使用 `QUARANTINE_BENCHMARK_QA_ROOT=docs/validation/reactor-induction-v1/final ./tools/validate_quarantine_benchmark.sh` 运行任务/旧场景、实际命中、原生镜头、带输入的实时演示和无截图启动器。实际操作路径与直接状态检查分开。默认ML29地形、HIGH阴影、暖雾不变。演示有编排，不是无人干预通关。
- 首轮 `validation/native.log` 有一项 `replay_unpauses_scene false`。它同时检查解除暂停和重播用时小于3秒，不能从该结果确定是哪一项或归因于着色器；最终在相同断言下重跑通过，未放宽阈值。不宣称偶发问题根因已解决。
- 入口：新版实玩 `launch-quarantine.command`、演示 `launch-benchmark.command`；`launch.command` 和 F5 保持原训练场。无新增 Tripo/imagegen/混元调用。

实际启动器无截图演示，macOS / Apple M6 / Metal Forward+ / 1920×810：新版平均59.972 FPS、P95 17.374ms，旧塔效果同场对照59.970 FPS、P95 17.402ms。两次都接近60FPS，在本次窗口条件下未测出明显差异；不能据此推断没有GPU成本，也不与历史103FPS直接相减。原有Metal退出时Texture RID警告仍未定位。

**下一项优先打磨**：在同一段正常追逐中侧拍T-Bug，先解决支撑脚随身体滑动，再验收转弯、坡道和命中反馈；不优先再加远景面数或全屏光效。
