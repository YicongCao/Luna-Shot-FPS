# ML11 — 枪械视觉倒退复盘与保形原则

日期：2026-11-16。性质：对既有原生证据与生成代码的复盘，不修改运行时资产，不新增生成任务。默认继续使用 ML06。

**结论：ML07 的主要失败是重建时丢掉了 ML06 的形体设计与装配层次，再试图用更完整的材质、微细节和烘焙流程补偿。ML09 恢复了部分局部特征，却继续沿用了已经退步的主体。实施者把“受控、规整、可验证”误当成了“视觉更好”，并在已有截图足以发现问题时给出了过于宽松的视觉通过判断。这个责任在实施与复查，不在用户要求提高质量，也不能归咎于付费工具或 Godot。**

## 本次实际检查了什么

读取 [三版对照页](../validation/ls01-refine-v2/review.html)及其生成器，直接打开该页引用的三版原生 PNG，逐组比较 14 个视图、共 42 张：整体；弹夹两侧与暖掠射光；枪托两侧；斜接；瞄具正面、侧面、背面；屏框正面与侧面；线圈护罩两侧。为方便并排观察，临时拼图只做缩小排版，未改变曝光、色彩或内容；判断依据为仓库原图。另看原概念图，核对建模、材质、导出、截图和验收脚本。

[截图脚本](../../tools/ls01_refine/structure_capture.gd)为三版使用相同相机参数、1600×1000、中性灯组，关闭能量与 Glow；弹夹另有同设置暖掠射图。因此这些结构差异不能解释为单纯换了镜头或 Bloom 强弱。本次没有重新跑三版 Godot、没有做旧几何/新材质交叉替换实验；材质影响的精确占比不作定量结论。概念图也不是可用于测量背面结构的工程图。

ML06 仍有软边、错误警示条、矩形屏框等既有缺点。用户选择 ML06，表示它的整体视觉优于当前返修版，不表示这些缺点已消失或概念还原已验收。

## 为什么代码会生成这样的结果

### 1. 把修整升级成了没有保形约束的重新设计

[ML06 日志](ML06-工业细节与使用痕迹.md)记载：主体指定面的受限拟合单点移动不超过 1.5 mm，保留连接关系与 UV，再烘焙。它在有缺陷但已有设计层次的原枪上做增量修改。

ML07 的 [build.py](../../tools/ls01_refine/build.py)则直接用 `profile()` 创建机匣、枪托和弹夹。该函数将二维外轮廓等宽挤出，并用完整前后面封闭。`T08_StockShell` 没有镂空轮廓或开孔步骤；因此枪托变实心是建模配方本身决定的。弹夹由一个外轮廓和 `box('T11_CellSide', ...)` 薄板构成，原卡扣、端盖与高差没有被录入。瞄具是前后两个环，脚座是方盒，顶部六个方块替代原来的多层装配细节。

[export.py](../../tools/ls01_refine/export.py)按 `replaced_prefixes` 删除旧部件，再装入新件。这不是只给原模型换了材质，也不是旧细节在导出时偶然丢失；主体设计在重建时已经被简化。保留名义外包尺寸、动画挂点或红点轴，不能保证轮廓、空隙、比例和体块关系不变。

### 2. “高低模齐全”掩盖了共同母形过于简单

`pair()` 由同一个基础网格复制高低模，高模补少量布尔细节、三段倒角和程序化微表面，低模使用一段倒角。这种方法可以做规则机械件；但当基础网格本身没有枪托镂空、分段弹夹和复杂脚座时，两者都缺这些设计。真实的 cage 和真实的 Cycles 烘焙可以传递已有表面细节，不能创造被省掉的体块与空洞。

因此，失败不是“没有进行高低模烘焙”。此前确实做了；**失败发生在烘焙前的形体设计，之后流程越完整，只会越稳定地复制错误设计。**

### 3. 将结构斜面与细小倒角混为一谈

ML07 主体常用约 0.7–1.2 mm 的规则倒角，适合处理锐边，但不能替代原版有独立面宽的结构斜面、双棱和层叠台阶。原图中的一些亮带来自这些较大几何面，其投影在正常游戏尺寸下仍可读；换成窄边后，再用掉漆条补亮线，观感仍是平板。

ML09 的 [structure_v2.py](../../tools/ls01_refine/structure_v2.py)确实补了变截面八角枪托、鳍片和弹夹附件，却继续采用封闭枪托与同一机匣母形。局部从 07 改善，不等于整体已经追上 06。

### 4. 材质多了，形体与材质的配合反而弱了

三版同光照图里，ML06 的折面、接缝和深色连接件让高光明暗交替；ML07 大面积漆壳上主要剩下淡划痕与斑点，画面读起来更平、更均匀。暖掠射图能看到 07 的凹痕与表面变化，说明细节不是完全没生成，而是它们承担不了被删掉的中尺度结构。

`build.py` 的材料使用通用物体空间 oil/wear 图案、噪声和 `localize_edge_mask()` 包围平面距离代理。它们可复现，却没有自动理解装卸接触、握持位置、真实边缘或零件的磨损故事。没有人工分区时，容易形成多块大板上相似的斜向擦痕与点状脱漆。`retained_materials.py` 也修改了保留件的底色、粗糙度、金属度，并改用微法线叠加前的旧烘焙法线；“保留几何/UV”不等于保持原来的全部外观。

这里应区分三件事：漆面设置非金属并非错误；不应为增加金属感把整枪 metallic 设成 1。新旧材质与几何同时变化，使因果难以拆开；不能仅凭截图断定某个粗糙度值、压缩格式或 imagegen 是唯一原因。本次最确定的主因仍是几何和色块层次丢失，材质规则没有补足它们。

### 5. 资源预算增长，没有转化成关键视觉信息

[ML07 当时报告](../validation/ls01-refine-v1/REPORT.md)按同一“含运行时网格”口径，ML06 为 28,372 三角，ML07 为 39,748，增加约 40.1%。新增面数用于管线、螺钉等小件是可见收益，但整枪轮廓反而更贫乏。这不是面数预算迫使我们把枪托封死、弹夹抹平，而是预算与实施注意力的分配失衡。

新 UV 无重叠、扩边充分，并不能证明细节在第一人称尺度可读。报告中主体/附件 UV 覆盖率约 51.7%/26.1%，说明也不能把“新 atlas / 4K 母版”直接称为更高有效精度；本次不据此推断所有模糊都由 UV 导致。

## 验收为什么没拦住：实施者的判断失误

[ML07 visual-review.json](../validation/ls01-refine-v1/visual-review.json)将 R11 判为通过，理由是“受控几何、灰模平面和窄倒角稳定”，剩余问题主要列旧保留件的软边。**这个判断漏掉了新件自身的大幅形体退步。** R07 以“六边形、内嵌玻璃、四角螺钉成立”判过，也没有检查六个角的位置、框的粗细及与主体的比例。

[ML09 structure-review.json](../validation/ls01-refine-v2/structure-review.json)验证双棱、八角、六片鳍片、卡扣等局部存在，仍没有对“镂空必须保留”“脚座总体积和轮廓不得退步”“原有色块不得无故删除”作比较。[数值审计](../../tools/ls01_refine/audit_structure.py)检查了数量、部分坐标、屏端点位置和红点净空；这些证据有效，但覆盖不了整体设计。人工视觉复查本应补上这个缺口，我没有做到。

过去记录了 `user_acceptance: pending`，但又将 `implementation_review: pass` 的候选设为默认。保留“待用户验收”字样并不能抵消默认替换造成的实际退步；用户最后成了发现基础结构损失的那一关。ML10 已将默认选择与 APPROVED 技术标记解耦。

**更正口径：** 历史几何/UV/功能等真实检查继续有效；ML07 的 R11 与 ML09 的“整体结构还原通过”不能再作为视觉升级已成立的依据。原 JSON 留存作为当时判断的证据，本复盘追加纠正，不伪造历史或把真正通过的技术测试改成失败。

## 后续必须采用的工作方式

1. **先列不可损失的设计，再列待修缺陷。** ML06 的枪托大镂空、内骨架、白黑橙分区、弹夹体块高差/卡扣/端盖、瞄具脚座和导轨层次、前罩斜切与开槽列入保留清单。任何删除都必须作为明确设计变更说明，不能藏在“清理拓扑”里。
2. **修一个可见问题，保持其余条件稳定。** 优先在 ML06 上独立修屏框、某颗螺钉或一块材质。几何和材质分阶段；新 UV 无法直接套旧贴图时先比较同一中性灰材质几何，再在固定几何上比较材质，不能强行错套 atlas。
3. **先核对外轮廓和镂空，再看装配，再看表面。** 灰模/剪影下，左右侧、正面、三分之四视角与正常第一人称尺寸都不能退步。结构不通过就停止高模微雕刻与整套烘焙，不把“已有很多工作”当作继续推广理由。
4. **验收写形状关系，不只写零件名和数量。** 八角还要看宽高、上下收放、厚度、脚座比例；弹夹还要看端盖收缩、段间高差和轮廓；屏框还要看端点位置、边框厚度和嵌入深度。装配空隙与高光面宽也是交付内容。
5. **同时看获得了什么、失去了什么。** 每次同镜头 A/B 必须逐项记新增收益、丢失特征及其严重程度。轮廓、镂空或主色块损失属于阻断项，不能用“钢螺钉更真实、通道更完整”抵销。
6. **用游戏尺寸决定细节优先级。** 优先保住大轮廓、中尺度装配和清晰高光，再分配面数/UV 给螺槽、微坑与擦痕；材质室放大图只用于排错，不单独决定整枪升级。
7. **保留成功的局部，不捆绑整个失败版本。** 弯曲铜管、钢色十字紧固件、连续警示条和异形屏框可作为独立候选迁回 ML06，但必须重新检查安装与视觉；本轮只记录方向，不自动迁移。
8. **默认版本跟随用户已选基线。** 自动检查负责找错误，实施视觉比较负责明确收益与损失；用户判断优于当前候选时保留基线，不以完成里程碑或新增技术为由自动升级。例行构建和验证无需重复授权。

这次最应留下的经验是：**先保护已经好看的设计，再提高制作精度。精度是把目标做准；把复杂设计换成容易编程的简单形体，再把简单形体做得很规整，不是同一件事。**
