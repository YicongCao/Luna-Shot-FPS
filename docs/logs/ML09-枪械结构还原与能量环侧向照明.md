# ML09 — 枪械结构还原与能量环侧向照明

日期：2026-11-16。状态：已实施并启用默认ML09；技术与本轮结构复查通过，用户验收待定。

## 问题与决策

用户指出 ML07 材质改善的同时丢失了 ML06 / 概念中的机械形状：规则对称屏、枪托少了一层倒角、接口变直、瞄具少角及前后鳍片、弹夹成了平板。以 ML06 为弹夹结构基础，受控几何重建并保留 ML07 材料分层，重新打开上述视觉检查。概念与原生图不能互相替代。

## 阶段一：结构

独立 `ls01-refine-v2` / `ls01_v2` 候选，保留 ML06/ML07。真实宽倒角截面、榫接式黑白斜切、八角瞄具及前后各三片安装鳍片、下移端点的异形六边屏及同形底座、分段弹夹和开窗护罩。所有新增件保存高/低/cage，主体与附件重新展UV。运行时选择 `--weapon-revision=ml06|ml07|ml09`，不传参数仍使用已验收候选逻辑。

灰模检查中发现弹夹端部螺钉悬空，改到有面板承托位置；护罩下肋补内支撑条，末端补接合套筒。低模拓扑、正体积、cage对应与UV严格重叠检查通过。原生Godot灰模证据在 `../validation/ls01-refine-v2/`。

## 经验

- 材质改善不能抵偿轮廓退步；先把“几个角、几层面、几处连接”写成可观察的结构条目。
- 宽倒角应是独立截面带；窄倒角修饰只能负责高光，不能吞掉原有面。
- 高模浅槽可以烘焙，但端盖、卡扣、镂空、弯曲和装配连接必须留在低模。
- 版本目录不仅是输出参数：运行时材质、审计、截图与发布也必须选择同一版本，避免串用旧UV贴图。
- 当前阶段不宣称最终视觉验收；材料、补光和性能后续验证。

## 调用费用

本轮新增 Tripo 0 次，imagegen 0 次；复用 ML07 两张遮罩，无新增付费生成。

## 阶段二：重烘焙与材质

170组高低模/cage（含接合套筒与内支撑）完成独立body/kit整atlas的4K Cycles烘焙；运行时约38,797静态三角。主体法线4K，其余运行通道2K。九个未重建零件保留原几何与UV，原ML07贴图不被覆盖。12通道PNG及Position EXR、实际投射场景保留。

原生中性/掠射光复查可看到弹夹浅斜槽、分段与卡扣，枪托宽倒角双棱、黑白斜接、八角瞄具及前后装置；屏玻璃在同轮廓框/底座内，四颗金属十字螺钉可见。此为结构和烘焙复查，不代表用户认可所有磨损艺术效果。

一次打包启动早于附件烘焙完成，缺图检查报错，未发布默认资产。已增加整批烘焙完成门禁；失败日志留在rejected，不完整预览留本地artifacts；完成后重新打包并通过bake-audit。经验：阶段完成应由报告和进程状态确认，不能仅看其中一个组的“BAKE_COMPLETE”。

## 第二次法线复查

在反侧掠射光下发现弹夹面板的斜向明暗与缺角槽痕。低模平面逐角法线点积检查定位到三角化修改器默认未保留custom normals：部分法线与几何平面法线点积仅0.792。ML09三角化改为`keep_custom_normals=True`后，同一位置提升到0.999977，未动轮廓或添加伪补丁。旧body/kit烘焙缓存作废，重新烘焙；增加源低模与实际glTF导出面的法线检查。该项再次说明“已三角化”不等于“烘焙切线输入稳定”。修正前图和检查日志保存，未将其当作做旧通过。

## 阶段三：侧向补光与默认接入

保留两盏近距Omni，左右新增各一盏带阴影Spot（0.43m、53°、能量0.20）；保留原横向光晕/Bloom，四灯统一受F6/F9控制。小阴影偏移初值产生条纹，修正后真实挡板仍能遮光。补光比较关闭Bloom，采样实际结构表面；肋片自由边缘的错误采样点重新定位到内支撑，没有降低判定阈值。

全部源/UV/烘焙/导出检查、75项弹量检查、原生射击/命中/换弹/红点/超宽/F2/F3及13项光照检查通过。完整武器39,145三角、36网格实例、7材质。ABBA ABBA的P95中位数ML07为35.595ms，ML09为27.8885ms，纹理内存计数均815.99MiB。满足相对10%门槛；单轮波动大，不据此声称确定加速或稳定60FPS。

已通过发布门禁启用ML09，原生默认启动及ML06/ML07回退检查通过。新旧环境资产哈希一致。保留用户验收pending及旧枪口/握把软边、字标和磨损艺术性差距，未把这次结构修正写成整枪完全等同概念。

提交节点：1cab9c2（灰模/结构）、8922c22（首次烘焙）、c3efd06（保留custom normals并重烘焙）；最终补光和报告另为独立提交。

经验补充：计数检查不能排除面法线错误；先看无Bloom/灰模/仅法线，再看最终PBR。性能需保留每轮数据与波动，不能只呈现有利中位数。阶段失败保留证据，修好后重新验证，不能让旧通过日志冒充当前资源结果。
