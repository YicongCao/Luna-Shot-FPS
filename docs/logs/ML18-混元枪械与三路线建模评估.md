# ML18 — 混元枪械与三路线建模评估

日期：2026-11-16。任务：检查用户提供的混元高模、低模、UV FBX、PBR GLB，与Tripo全链路、ML06保留修整和ML07重建路线比较。费用：本轮没有调用生成服务；用户此前混元费用未知。

## 实际完成

归档四份原文件（哈希一致、LFS、`.gdignore`），检查几何、法线属性、UV和真实材质绑定；统一机位/光照/曝光采集53张Godot原生独立材料场景截图及27张Blender离线灰模。生成[对照页](../validation/hunyuan-weapon-v1/review.html)、[完整报告](../validation/hunyuan-weapon-v1/REPORT.md)与可复现脚本。67项原生导入/截图/统计检查通过。没有覆盖枪械、环境、训练场及默认ML06。

## 重要发现与经验

1. 混元高模1,992,214三角，最终低模20,901三角，保留了弹夹分段、镂空和装配层次；在这批约2万面样本中，结构辨识优于Tripo低模，更明显优于ML07。但灰模近景仍有软边和波浪阴影，不能把彩色图看起来更干净当作精准低模验收通过。
2. **文件叫“PBR”不代表通道齐全。** 本次只有一张8K底色，金属度0、粗糙度1，无贴图法线/AO/发光。完整PBR仍未交付；无法据此判断混元服务是否不支持，需要区分产品能力和拿到的文件。
3. **文件大小不能给建模质量排名。** 混元9.93MB的材质GLB含8K底色，Tripo6.96MB低模含18套共54张图；纹理大小、压缩和拆点都影响字节数。
4. **不能混淆ML06与ML07。** ML06保留Tripo高模，低模包含历史Tripo重拓扑与本地修复；ML07才是局部程序化重建并丢失设计层次。不能为支持某条路线而改写历史。
5. 只比较同一渲染设置下的同一范围。去掉后加工的动态屏幕、铜排等附件，分开灰模、原材质、高模来源和运行时主体；明确离线图不等于实机，静态材料场景不等于完整游戏回归。原始文件缺顶点法线时，导入器生成法线也会影响观感。
6. 单网格不等于适合游戏整合。混元需按功能分离弹夹、枪身和能量环，验证新UV/法线与烘焙关系；不能直接套用Tripo贴图或按旧节点名绑定。

## 选择与边界

新几何试验优先混元；完整自动PBR与现成分件程度目前Tripo更齐；当前已接入游戏继续ML06；不推广ML07整体重建。下一步先确认是否漏导出PBR通道，再做混元弹夹/机匣局部烘焙与材质样板，保留造型并验证第一人称。没有自动启动重制或付费任务。

实施视觉复查已完成，问题保持开放；未进行混元整枪游戏接入、动画、性能和用户验收。此次只是文件与候选路线评估，不是新枪械版本发布。
