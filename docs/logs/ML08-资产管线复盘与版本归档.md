## 可复用的工作经验

1. **先验证小样，再推广整枪。** 一次同时处理所有渲染技术容易让每项都停留在中间质量。先用弹夹、十字螺钉、屏框和铜管验证轮廓、烘焙、材质与原生画面；失败时修正样板，再扩展。
2. **机械精度来自受控几何。** 增加高模面数不能修复融化的轮廓。平面、窄倒角、槽孔和接口应可参数化；弯管、薄片间隙和屏框剪影保留几何，浅痕和微坑交给高低模烘焙。合格旧件可保留，不将“局部返修”描述成“全枪重建”。
3. **烘焙要有明确契约。** 固定低模三角、逐角法线、UV 与导出切线；逐件建立 cage、隔离串投射；修改这些数据后作废旧结果。源文件哈希不能发现所有烘焙算法变化，脚本改变时也必须清理相关缓存。辅助图的坐标编码、颜色空间和范围需验证。
4. **材质需要关联的物理层。** 漆面保持非金属，露底遮罩联动 BaseColor、Metallic 和 Roughness；油膜、积尘、钢、铜、橡胶应有不同反射。不能靠把整件设为金属、提高 Bloom 或铺满随机划痕改善质感。
5. **imagegen 用作艺术输入。** 油污与不规则磨损图案适合作为遮罩，不能直接视为完整 PBR、测量高度或结构设计。微表面仍需要控制尺度、密度和方向，保留干净区域。真实高模 Pointiness 与人工边界距离遮罩分别保存，避免把代理图误称真实曲率。
6. **引擎实机才是最终实现证据。** 使用同机位、曝光和分辨率对照；先关闭 Bloom/光晕，再检查中性光、掠射光及关卡光。功能断言、技术审计、实施者视觉复查、用户验收分别记录，不能互相替代。
7. **按缺陷分配清晰度与性能预算。** 2K 主体螺钉槽口不足时，用固定近景证明后只提高必要法线通道。全主体 4K 的性能版本被否决，最后采用主体法线 4K、其他通道 2K、GPU 压缩与 mipmap。性能用 ABBA ABBA 多次交替测量，记录全部样本和负载边界，不挑最快一次。
8. **复用与隔离控制成本。** 环境限定模块数量，机械附件复用原型；源文件按零件保留，运行时按材质和动画关系合并。候选输出与默认资源隔离，发布标记保护已验收资源，保留旧版入口以便回退。

## 首次大资产上传的经验

首次一体化 SSH push 在等待 LFS 上传时被 GitHub 关闭连接，本地提交没有丢失。改用 HTTPS origin，复用已完成对象，先独立执行 `git lfs push origin main`，再执行普通 `git push -u origin main`，避免 Git 传输连接长时间等待资产。

LFS 上传工具记录 796 个唯一对象、约 2.6 GB，全部上传完成；工作树中多个路径可共享同一对象。开启进度输出有助于区分正常的大文件等待和连接故障。不要因终端暂时安静而反复重启上传，也不要用强制推送解决传输问题。
