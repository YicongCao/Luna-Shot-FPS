# ML17 — Tripo主导枪械重制与建模流程复盘

2026-11-16。状态：用户确认后已完成两项Tripo任务，共55积分；Godot独立候选检查完成，软边与局部阴影问题保持开放，尚未替换默认ML06。当前默认ML06保留至候选视觉比较完成。用户要求先记录对照与意见，再从枪械重新尝试Tripo低模/PBR。

## 当前流程与对照

ML15环境：imagegen概念/规格→Tripo详细分件高密度候选→归档作参考→Blender从空场景按程序配方重建高低模→本地分组UV/cage、Cycles烘焙与分层PBR→Godot验证。Tripo网格没有作为环境最终烘焙源。规则配方提供尺寸和接口控制，却损失了部分生成模型已有的装配设计。

枪械历史不同：ML06高模主要保留/修整Tripo密集几何，低模来自此前Tripo重拓扑和本地修复；ML07则局部重建主体。旧Tripo低模任务db8a68c0-6b4e-415c-9143-718ea2c58ded参数为20,000三角、smart_uv=true、bake=false，实际35积分；随后单独Tripo纹理任务与本地材质修整。因此不能将ML06软边完全归因于本地程序减面，也不能宣称此前没有尝试Tripo低模。

[完整源模型/PBR图集](../validation/source-mesh-comparison/review.html)，灰模为真实源文件Blender离线检查，非游戏实机，统一机位/灰材质，无烘焙法线。ML07高模图含相同保留低模作装配参照；B2静态图排除游戏独立风扇和灯具。

## 用户意见（记录为用户视觉判断）

用户认为Tripo原始网格效果很好；ML06本地高模因基本保留密集几何而接近原始结果。ML07本地高模的面数和细节过少、模块边缘变软，视觉上已像低模；ML06低模也暴露软边/细节损失，ML07低模在用户判断中已不可用。用户以高模约50MB、低模约800KB说明压缩幅度，并判断当前Codex使用Blender处理生成网格的能力不足，愿意增加Tripo预算来换取更好的视觉结果。

用户提出工作流：Codex/imagegen准备N视图和效果图→Tripo高模→Tripo低模→Tripo PBR。本轮先复用认可的枪械原始高模，重新尝试Tripo低模和贴图；并非授权将所有资产立即重做。

实施判断：接受“保持生成设计，减少整件重建”的方向。文件体积也受格式、压缩、材质嵌入影响，不能作为细节质量的唯一指标；同样，高模灰模和低模未加载法线的比较不能单独证明最终材质。应同时比较无贴图几何、加载服务端贴图的结果与Godot实机，记录每一步的收益和损失。

## 本轮候选方案

复用原始约193万三角分件枪械，不重新生成概念/高模；避免多视图重新解释已认可形体。完整新枪设计将来需要一致的多视图，但当前只重做已有高模的下游。

1. tripo_texture：原始高模GLB，v3.5，detailed，PBR=true，delight=true，bake=true；参考原枪概念，用象牙白涂漆、深色框架、橙色能源盒和青色能量环，保留镂空和分件。预计20积分。
2. tripo_decimate：使用上一步带PBR高模，v3.0，20,000三角、quad=false、smart_uv=true、bake=true，将已有纹理转移到低模。预计35积分。这是该算法的整件上限，不能擅自传60k；若视觉仍失败，保留失败证据，另讨论分件预算或其他受支持路线，不自动重抽。
3. 下载两阶段产物、费用核对；只读提取贴图/统计分件/观察高低模，再制作同机位候选对照与Godot检查。Codex只做坐标/单位、导入、材质连接与必要接口适配，不整件重建或重做PBR。

预估55积分，最终按usage核对。Tripo texture的bake是材质效果烘入，decimate的bake是原纹理转移；公开工具没有独立“指定高模+指定低模+cage烘法线”的接口，因此不能预先承诺服务执行了与Cycles完全相同的高低模法线投射。必须检查实际输出是否含normal、何种细节被保留；材质图生成成功不等于精确几何细节已烘焙。

当前Tripo工具要求先展示返回计划并获得确认，再调用计费功能。此次日志/对照阶段独立提交；新任务完成后另补任务ID、实际费用、失败与修正、候选视觉结论，不提前记作成功。

官方能力与价格核对：[重拓扑](https://developers.tripo3d.ai/en/docs/mesh-decimate)、[纹理](https://developers.tripo3d.ai/en/models/texture)、[价格](https://developers.tripo3d.ai/en/pricing)。

## 本轮执行结果

已按确认执行高模PBR→Tripo低模/UV与贴图转移，实际20+35=55积分。任务分别为212a9dac-9cdb-43e5-9379-75ea6bf74903、beeb5377-422a-4028-bc0d-a452188847a9，usage账单核对通过，0重抽。高模1,934,290、低模20,303三角，均18网格/18材质/54图像，低模实际略超20k请求。返回材质均带法线，没有独立Emission或AO通道。

原生Godot同机位PBR、灰模、关闭法线共12图/14项检查通过，法线有实际像素响应；但低模软边和三角起伏仍明显，故技术导入通过与美术未达标分开记录。证明保留Tripo高模能保住更多装配设计，不能证明只换成Tripo低模就能解决全部质量问题。本轮原始枪械不含后来工业kit/弹药屏，且没有接入开火/动画，不替换默认ML06。

## 高模直接进入训练场与低模平滑诊断

按用户要求，将服务原始高模直接加载到完整关卡的独立武器视口，分别关闭/开启Normal，恢复0.905m枪长，只替换测试进程视觉。macOS Apple M5/Godot4.7.2 Compatibility；窗口1600×1000、武器视口1440×900，无VSync/帧率限制，各5秒预热+60秒。同机位出生区左右扫视，不射击、不移动胶囊；现有场景动态和后期继续。没有接入新武器功能或更改默认ML06。

独立两轮normal-off平均156.7/65.7FPS，normal-pbr73.1/86.1FPS，ML06一轮147.5FPS。波动大，不能选最快值或把首次差异归因于Normal。诊断观察后台Chrome渲染进程高CPU，未关闭用户应用；热警告查询无记录不等于证明无降频。追加同进程交替六段各10秒、排除段首1.5秒：off97.1–122.5FPS、on79.7–104.6FPS。全部数字与限制保留；可说明高模在本机能实时渲染，不能承诺其他路线或后台状态稳定60FPS。

低模使用相同顶点/UV，诊断shader替换为逐面法线，与原平滑灰模比较。去掉插值后鼓包感减少但显露三角分面，轮廓/几何损失没有自动恢复。该诊断不写回GLB，也不是正式修复；正式改顶点法线仍应重做相关烘焙。

当前公开Tripo API重拓扑参数没有smooth=false/硬边角度；Studio文档有500–50k和Smart Mesh P1.0开关，不能混同API v3.0的20k上限或关闭平滑。通用博客提及Smoothing Pass，缺少对应本次接口字段，不能冒认已可调用。v1基础减面支持更高面数但缺少bake，后续需要另外规划预算；本次新增付费0。

用户可在官方在线Viewer打开本地GLB查看；API平台History查任务/费用，Studio上传外部网格也可检查。未核实API资产自动同步Studio Models，不编造task_id直达链接。详细参数、官方来源、截图与完整FPS证据见[高模性能与平滑诊断](../validation/tripo-high-performance/review.html)及[核查文档](../validation/tripo-high-performance/PARAMETERS.md)。
