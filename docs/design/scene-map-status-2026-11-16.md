## 建议下一步：ML17 场景构图与地图编辑收尾（提案，未执行）

建议先完成一条“出生点 → 中央能源设施 → 高架出口”的实机视觉样板，再扩展到全场，继续保持六种主题资产预算。

1. **建立可保存的人工布局调整。** 在固定种子生成后、合法性校验前应用按稳定模块ID记录的override；先支持位置、90°朝向与明确批准的标记位置，仍限制数量、占地、射击线和净空。重建应保留这些调整，冲突必须报错。先做数据往返与预览，不急着开发大型编辑器插件。这样后续构图修改不会依赖直接改生成文件。
2. **精修正常第一人称构图。** 利用现有A/B塔的排列和朝向，明确入口、能源中心、检修区域；检查近处高塔是否抢占画面、是否遮住信号塔、相邻设备有没有过密。先固定三个实机机位，列出相对当前版的收益与损失，保持通行和训练接口。
3. **补齐边界与远景的空间关系。** 当前灰色围墙和纯黑背景使场景更像测试场。建议先用低成本的围界分段/基础结构与场外月面地平线剪影做样板，让设施有落在月面的感觉；这是基础设施和背景预算提案，下一期确定范围，不额外引入大量建筑。保留黑色太空方向，不用浓雾或炫光掩盖边界。
4. **最后统一明暗与标识。** 在构图稳定后处理白色壳体高光、暗部层次、区域编号和少量有意义的检修标识；不把每块表面塞满污渍。保持现有灯具与Compatibility方案，先关Bloom检查，再恢复特效。背景与环境反射可能关联，改变背景时应单独复查金属与地面，避免只为远景破坏已认可的材料效果。[Godot Environment说明](https://docs.godotengine.org/en/4.7/tutorials/3d/environment_and_post_processing.html)

优先级建议：**可保存的布局调整 → 一段实机构图样板 → 围界/远景 → 全场统一检查与打包**。相比继续给每个模块追加微小螺丝，这条路线更直接针对当前整场观感的不足。弹着破损、碎屑、环境交互另开后续范围，本次仅保留月壤资源。
